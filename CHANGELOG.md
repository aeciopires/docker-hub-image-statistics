## [1.0.0] - 2026-11-17

### Added

- Discovery of public images by namespace (user/organization) and explicit
  repositories, with include/exclude globs.
- Pull statistics per image and in total: cumulative, last 1, 7 and 30 days,
  and hourly series (`/api/v1/images/{ns}/{name}/history`).
- Configurable collection interval (default 1h) with last/next update in the UI,
  API (`/api/v1/status`) and metrics.
- Docker Hub rate-limit handling: client-side pacing (60 req/min anonymous,
  150 authenticated, anonymous maximum 180), `X-RateLimit-*` awareness,
  `Retry-After`/exponential back-off and minimum intervals.
- Optional Docker Hub authentication with a personal access token.
- Cache tiers SQLite → disk (JSON) → memory with fallback and warm-up.
- Configuration through YAML, `DHIS_*` environment variables and defaults.
- Web UI following Material Design 3, dark mode by default with a light/dark
  selector, fully self-contained (fonts, icons and favicon embedded).
- JSON logs with level (default `INFO`) and trace correlation.
- Prometheus metrics, OpenTelemetry traces and logs over OTLP/HTTP.
- `/healthz`, `/livez` and `/readyz` endpoints and a `healthcheck` command.
- Distroless, non-root, multi-arch Docker image.
- Helm 4 chart with probes, restricted security defaults, NetworkPolicy,
  Ingress, Gateway API HTTPRoute, `extraObjects`, ServiceMonitor and Grafana
  dashboards; README generated by helm-docs.
- Docker Compose for the application and for an observability stack (OpenTelemetry
  Collector, Prometheus, Loki, Tempo, Jaeger and Grafana).
- Grafana dashboards for image statistics and for service metrics, traces and logs.
- Makefile targets for dependencies, tests with a 90% coverage gate, builds,
  image build/push/scan, compose stacks, Helm and documentation checks.
- Pulls in the last collection (difference between the two newest snapshots)
  per image and in total: UI card and sortable column, API
  (`last_collection`, `pulls_last_collection`, `?sort=last`), the
  `dockerhub_image_pulls_last_collection` metric and Grafana panels.
- Configuration reload on `SIGHUP` without exiting; invalid configurations are
  rejected and the current one keeps running.
- Makefile targets `reload`, `compose-reload`, `kind-create`, `kind-delete`,
  `kind-load`, `kind-up`, `helm-install`, `helm-reload`, `helm-uninstall`,
  `helm-status`, `kind-port-forward` and `kind-logs`, plus `deploy/kind`.
- `kind` and `kubectl` in `.mise.toml`.
- Command line built with Cobra: POSIX short/long flags (`-c`/`--config`,
  `-h`/`--help`, `-v`/`--version`, `-a`, `-l`, `-n`, `-r`, `-i`, ...), generated
  help, `config` command (validate and print the effective configuration,
  secrets redacted), `version -s` and shell `completion`. Exit code 2 for usage
  errors.
- Configuration loaded with Viper: flags now override `DHIS_*` variables, the
  YAML file and the defaults; durations accept days (`90d`) everywhere.
- macOS uses Colima as the container runtime: `colima-start`, `colima-stop` and
  `colima-status` targets and Colima checks in `make check-deps`.
- Restarts, rollouts and reloads keep the collection schedule when the cache
  holds a recent collection; targets without cached data are collected
  immediately.
- Docker Compose mounts the configuration directory so edits reach the container.
- `make run` builds and runs the binary (so `make reload` can signal it).
- `scripts/validate-mermaid.sh` keeps its work directory in `.tmp/` inside the
  repository (Colima only shares `$HOME` with its VM).
